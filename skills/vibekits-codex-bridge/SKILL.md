# VibeKits Codex 桌面—手机桥接

## 目标与范围

桌面 VibeKits 是本机中转，手机通过既有认证中继发现并操作获授权的 Codex 原会话；合并到手机会话列表，保留来源隔离，使用真实 Codex 标识而非 VibeKits 动态图标。不要另造独立聊天产品或把 Codex 记录伪装成原 Harness 会话。

先确认本次验收层级。若用户只要源码修改、静态分析和编译，不启动应用、不读取真实聊天来“顺便验证”，也不擅自部署。编译成功可以是约定验收标准，但不是运行正确的证明。技能本身不授予安装工具、发布、启用远程访问或改变安全设置的权限。

## 工作流

1. **固定真实基线。** 读取仓库指令、构建资格文件、实际 pubspec 和依赖锁文件；记录 main 的实际 SHA、版本及来源。README 版本可能陈旧。ZIP 可用于编辑，但不能冒充具有 origin/main 的合格 Git checkout。
2. **先检查工具链和门禁。** 分别记录 Dart/Flutter、宿主系统、原生 SDK、编译器、签名条件。若预构建资格为 BLOCK，保留原错误，改做可完成的源码检查；不能伪造 .git、执行身份或跳过资格脚本。Linux portable C++ 编译不等于 Windows/macOS 产品编译。
3. **核对协议而不是按名称猜能力。** 对照安装版本及官方 app-server schema。CLI、MCP、桌面进程和现存 owner 服务不是同一个对象。OpenManus 的 MCP 连接生命周期可以参考，但不能推导出它实现了 Codex 原会话手机控制。涉及具体版本/API 时重新查官方来源，不把本案例的版本永久固定为最新。
4. **沿完整路径修改。** 本地来源授权 → 桌面发现/历史/控制 → 既有认证中继 → 手机 client/model → 合并列表与详情 → 回执/取消/权限失效。发现来源不等于获准读取所有项目；远端参数不能自行授权本机路径或 profile。
5. **拆分验证。** 先运行仓库已有检查，补充针对缺陷的行为夹具，再做 Dart 类型分析和目标平台编译。没有工具就明确 NOT RUN，而非用正则测试替代。复杂并发/权限修复请独立评审冻结版本，避免评审过程中继续改同一树。
6. **冻结交付。** 保存精确基线、完整及增量 patch、修改文件清单、SHA256 manifest、命令和退出码、尚未执行的检查、剩余功能缺口。对真实基线执行 patch apply-check。只在授权范围内提交或上传，发布前检查无凭据、真实会话、私人日志和机器私有路径。

具体并发、权限及平台排错见 [工程检查与案例记录](references/engineering.md)。该记录区分已观察结果、源码候选与待验证步骤，不应把历史测试数量当成未来通过标准。

## 最低工程约束

- 保留现有 local-private-read 边界；新增来源能力需独立授权，绑定账户、主机、项目、thread、source instance 和 owner epoch。授权在异步读写前后复核；撤销后迟到结果不得复活。
- 读取持久化历史、恢复线程、连接原 owner、控制运行中 turn 分开建模。`thread/resume` 不证明接管另一进程的运行任务。读取工具不应偷偷变成远程任意 RPC。
- 写操作绑定实际 owner 和 turn；未知结果不自动重发。连接重建和进程重启需要持久化操作日志及权威状态核对，内存去重不够。
- 手机发送前准确说明实际语义：若协议只能 send-or-steer，不能声称原子“空闲时才发送”。恢复线程可能应用当前配置，必须展示并核对实际 cwd/策略，不能承诺旧策略原样保留。
- 只传递明确允许展示的内容。历史、实时文本、metadata 和缓存都要遵守同一展示限制；隐藏 reasoning/tool internals，不以新快照清除已确认限制。限制期间保留已授权且安全的 Stop，不顺带恢复发送或审批。
- 默认关闭未经目标平台验证的实现；不得通过放宽版本、去掉 owner/ACL 校验、TCP 回退或自动审批来让演示“跑起来”。

## 汇报格式

用四项短报告：本次改动；实际执行并通过的检查；未运行/失败及具体原因；下一步所需环境。分别说“源码已接线”“分析通过”“目标平台编译通过”“已打包/签名”“已部署/运行验证”，不要合并为笼统的“全部通过”。若用户要求定期汇报，尊重最新频率与暂停指示，不把项目临时要求写成永久规则。
